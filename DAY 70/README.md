# Day 70 - Git, GitHub & Version Control 🌳🔀

A conceptual/skills day rather than a coding project — focused on learning version control fundamentals: tracking changes with Git, working with branches, and collaborating through GitHub.

## 📌 What This Day Covers

Since this day is about tooling and workflow rather than a standalone app, there's no `main.py` — instead, the skills practiced apply to *every* project in this repo going forward.

### Git Fundamentals
- Initializing a repository (`git init`) and tracking changes (`git add`, `git commit`)
- Writing meaningful commit messages
- Checking repo state and history (`git status`, `git log`, `git diff`)
- Ignoring files that shouldn't be tracked (`.gitignore`) — e.g. `.env` files, `__pycache__/`, virtual environments, database files

### Branching & Merging
- Creating and switching branches (`git branch`, `git checkout` / `git switch`)
- Merging changes back into the main branch (`git merge`)
- Understanding merge conflicts and how to resolve them

### GitHub & Remote Collaboration
- Connecting a local repo to a remote (`git remote add origin`)
- Pushing and pulling changes (`git push`, `git pull`)
- Cloning existing repositories (`git clone`)
- Using GitHub for hosting, backup, and showcasing a portfolio of projects — exactly what this 100 Days of Code repo itself demonstrates

## 🧠 Concepts Practiced

- Version control fundamentals and why they matter for any software project
- Local vs. remote repository workflows
- Branching strategies for isolating work-in-progress changes
- Writing a clean commit history
- Using `.gitignore` to keep secrets and generated files out of version control
- Collaborative workflows via GitHub (forking, pull requests, cloning)

## 📚 Why This Matters

Every project from Day 1 through Day 100 in this repo has been tracked and pushed using exactly these skills — this day formalizes the version-control habits already being practiced throughout the challenge, and sets up cleaner workflows (branches, `.gitignore`, meaningful commits) for the projects still to come.
